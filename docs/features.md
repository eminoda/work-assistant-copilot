## 1. 录制（面向用户的基础能力）

**目标：** 把用户在页面上的真实操作变成可回放的 Workflow DSL，而不是手写脚本。

**采集范围：**

- 页面 input 输入（非密码）
- 按钮 / 可点击元素的 click
- 表单 submit
- 导航变化
- Tab 标签页激活、创建、关闭等（用于多标签场景）

**Selector：** 录制时提交元素快照（稳定属性、role、文本、css 等），由 `browser-recorder` 映射为 DSL 步骤。

**密码字段：**

- 浏览器会屏蔽 password 明文；插件识别到此类元素后，**不写入明文**
- 引导用户主动输入对应值，存入本地 credential
- DSL 中用 `credentialKey` 占位，执行时再解析替换

**人工介入（等待链接）：**

- 二维码、短信验证码等无法全自动的步骤
- 用户可配置「等待 URL 变化 / 匹配」作为衔接点
- 脚本识别到约定的跳转或 URL 模式后，再继续后续步骤  
  （设计已定，实现待落地）

**录制加强：文本选择 → 通知源**

- 录制过程中允许用户框选 / 点选文本元素并标记
- 该文本自动纳入「消息通知」关注点（例如禅道 Bug 标题、邮件主题）  
  （设计已定，实现待落地）

## 2. 执行

**目标：** 用 Playwright 回放已保存的 Workflow，覆盖自动登录、打开应用等重复操作。

**Cookie 约定（登录类型）：**

- 录制开始时记录「首次访问」cookie 作为 baseline（用于日志对比）
- 结束录制时保存该站点**完整终态 cookie** 为会话凭证（如 `workflow.{id}.session`）；仅 diff 会漏掉登录页已存在的 `GWSESSIONID`
- 完整登录成功后，Runtime 会用浏览器最新 cookie **回写**会话凭证，供下次预登录
- 下次执行：向停录时的 `homeUrl` 注入该凭证并打开页面；**若未发生跳转**（会话仍有效）则跳过完整工作流；若被重定向到登录页，再跑完整录制步骤
- 登录工作流步骤中不再回放 `setCookies`

**工作流类型（完成录制时必选）：**

- **登录**：记录最后一个 URL 为主页（`homeUrl`）。执行时默认：打开主页 + 注入 cookie；若页面未发生跳转，判定会话仍有效，**跳过完整工作流**；若被重定向到登录页等，再跑完整录制步骤
- **应用**：按步骤完整回放

**要点：**

- 经 Workflow Engine 逐步调用 `browser.open` / `click` / `input` / `setCookies` 等工具
- 步骤之间等待页面就绪（load / network 沉降），避免 SPA 未初始化就点下一步
- 桌面端或扩展触发 `POST /api/workflows/:id/execute`，执行在 Runtime 侧异步进行

## 3. 工作流组合

**原则：不推荐一次性录制超长复杂流程。**

推荐方式：

1. 分别录制短流程（如：门户登录、进入禅道、打开某项目）
2. 在桌面端 / Runtime 将多个 Workflow **组装**成组合流
3. **衔接判定：** 以上一步收尾 URL 与下一步期望入口 URL 的一致性（或可配置匹配规则）作为接缝

这样单段可维护、可替换，组合后仍得到完整体验。

## 4. 消息通知

**目标：** 把「主动进应用查询」变成「按策略提醒」。

**能力设想：**

- 人为定制：提示文案、关注事项、来源（录制标记的文本 / 外部轮询结果）
- 定时策略：间隔、工作日、具体时刻等
- 出口：系统通知（Desktop Agent）；后续可扩展飞书等

与「录制加强」联动：录制时标记的文本节点可作为通知模板或检测目标。

## 5. 周报 / 工作记忆（开发者场景优先）

**目标：** 主动沉淀每天发生了什么，支撑周报与更长周期总结。

**开发向流水线：**

```text
配置工作目录（项目根）
        ↓
Desktop 定时 / 手动触发
        ↓
Git 扫描（事实：branch、status、diff…）
        ↓
原始记忆入库（raw）
        ↓
接入 AI 模型分析 diff
        ↓
每个项目「每日代码总结」→ 纳入日报
        ↓
汇总为周报 / 更长周期报告
```

**原则：**

- 先存**事实**（diff、变更文件列表），再生成**总结**（模型输出），二者分离，便于回看与纠错
- 非开发场景可后续扩展「用户手记 / 邮件摘要」等输入源；当前设计以 Git 工作区为主

## 6. 与旧设计文档的关系

旧文档中的 Tool Registry、Zod 校验、禁止 LLM 直接出业务脚本、本地 token 等**工程约束仍然有效**。

本功能清单以用户愿景为准重排优先级：

| 更强调 | 暂缓或降权 |
|--------|------------|
| 录制质量、等待 URL、工作流组合 | 完整通用 Agent Loop 炫技 |
| 通知与定时 | 云同步 / 多用户 |
| Git → 日报 → 周报闭环 | 可视化万能 Workflow 编辑器（可先做轻量组合） |
