## 1. 录制（面向用户的基础能力）

**目标：** 把用户在页面上的真实操作变成可回放的 Workflow DSL，而不是手写脚本。

**采集范围：**

- 页面 input 输入（非密码）
- 按钮 / 可点击元素的 click
- 表单 submit
- 导航变化
- Tab 标签页激活、创建、关闭等（用于多标签场景）

**Selector：** 录制时提交元素快照（稳定属性、role、文本、css 等），由 `browser-recorder` 映射为 DSL 步骤。

**点击 → 跳转 / 新标签：**

- 录制时把「点击元素」与随后的同页跳转或 `_blank` 新标签绑定为一条主动触发（点击上记录 `resultUrl` / `resultTarget`）
- 其后的 302 / 多跳导航可写入录制（`navCause=redirect`），执行时**不**作为 `browser.open`
- 回放只执行点击；中间 SSO / forward 链接由页面自己完成

**密码字段：**

- 浏览器会屏蔽 password 明文；插件识别到此类元素后，**不写入明文**
- 引导用户主动输入对应值，存入本地 credential
- DSL 中用 `credentialKey` 占位，执行时再解析替换

**人工介入（等待链接）：**

- 二维码、短信验证码等无法全自动的步骤
- 用户可配置「等待 URL 变化 / 匹配」作为衔接点
- 脚本识别到约定的跳转或 URL 模式后，再继续后续步骤  
  （设计已定，实现待落地）

**录制加强：信息抓取 → 消息中心**

- 录制中点击「信息抓取」进入监控模式：悬停元素绿色闪烁边框，点击后抓取元素文本为 value，弹框命名（如「我的bug」）
- 可多次抓取；事件写入录制列表，并转换为 `browser.extract` 步骤
- 执行工作流时自动提取文本，写入消息中心（标题=工作流名，tag=`workflow`）
- 消息中心支持定时任务触发工作流；value 变更时主界面通知 icon 显示未读数字
- 消息按更新时间近→远排序

## 2. 执行

**目标：** 用 Playwright 回放已保存的 Workflow，覆盖自动登录、打开应用等重复操作。

**Cookie 约定（登录类型）：**

- 录制开始时记录「首次访问」cookie 作为 baseline（用于日志对比）
- 结束录制时保存该站点**完整终态 cookie** 为会话凭证（如 `workflow.{id}.session`）；仅 diff 会漏掉登录页已存在的 `GWSESSIONID`
- 完整登录成功后，Runtime 会用浏览器最新 cookie **回写**会话凭证，供下次预登录
- 下次执行：向停录时的 `homeUrl` 注入该凭证并打开页面；**若未发生跳转**（会话仍有效）则跳过完整工作流；若被重定向到登录页，再跑完整录制步骤
- 登录工作流步骤中不再回放 `setCookies`

**工作流类型（完成录制时必选）：**

- **登录**：记录最后一个 URL 为主页（`homeUrl`）。执行时默认：打开主页 + 注入 cookie；若页面未发生跳转，判定会话仍有效，**跳过完整工作流**；若被重定向到登录页等，再跑完整录制步骤
- **应用**：按步骤完整回放

**要点：**

- 经 Workflow Engine 逐步调用 `browser.open` / `click` / `input` / `setCookies` 等工具
- 步骤之间等待页面就绪（load / network 沉降），避免 SPA 未初始化就点下一步
- 桌面端或扩展触发 `POST /api/workflows/:id/execute`，执行在 Runtime 侧异步进行

## 3. 工作流组合

**原则：不推荐一次性录制超长复杂流程。**

推荐方式：

1. 分别录制短流程（如：门户登录、进入禅道、打开某项目）
2. 在保存弹框或列表「关联」icon 中设置**前置工作流**
3. **关联判定：** 前置工作流的末路径（`homeUrl` / 最后打开页）与当前工作流首路径（首次打开页）相同（origin + pathname）
4. 执行当前工作流时，Runtime **自动先执行前置链**（支持多层，检测循环），浏览器会话连续复用

（可视化组合编辑器可后续增强；当前已支持路径匹配关联）

## 4. 消息通知

**目标：** 把「主动进应用查询」变成「按策略提醒」。

**当前能力：**

- 录制「信息抓取」→ 执行时 `browser.extract` → 写入消息中心
- 消息标题为工作流名称，tag 为 `workflow`；列表按更新时间近→远
- value 变更产生未读，主界面通知 icon 右上角显示数字
- 消息中心可配置定时任务，按间隔自动触发工作流抓取

出口：扩展侧消息中心（后续可扩展系统通知 / 飞书）

## 5. 周报 / 工作记忆（开发者场景优先）

**目标：** 主动沉淀每天发生了什么，支撑周报与更长周期总结。

**入口：** Chrome 扩展主界面 ActionDock「周报」→ 按月倒序 → 自然周 Tab（周一为一周起点，Tab 倒序）→ 日报列表（`MM-DD`）→ 日报详情（事项 H1 + 描述 ul）→ 查看原数据（Markdown→HTML）。

**周划分：** 与当月相交的自然周（通常 4–6 周），编号为第 1…N 周；展示顺序为当月最后一周 → 第 1 周。

**数据：** `DailyJournal` 存结构化 `items`（简化版）与 `rawMarkdown`（原数据）。手写事项与 Git/AI 扫描合并到同一天。

**开发向流水线：**

```text
设置扫描根目录（scan.roots）+ OpenAI 兼容模型
        ↓
Desktop 启动 / 每小时 / 设置里「立即扫描」
        ↓
发现 git 仓库 → 昨日 commits → 变更文件
        ↓
事实写入 rawMarkdown；AI 总结写入 items（项目名作事项）
        ↓
扩展周报页按自然周浏览 / 手写补充
```

**原则：**

- 先存**事实**（commit、文件列表），再生成**总结**（模型输出），二者分离，便于回看与纠错
- 非开发场景可后续扩展「用户手记 / 邮件摘要」等输入源；当前设计以 Git 工作区 + 手写为主

## 6. 与旧设计文档的关系

旧文档中的 Tool Registry、Zod 校验、禁止 LLM 直接出业务脚本、本地 token 等**工程约束仍然有效**。

本功能清单以用户愿景为准重排优先级：

| 更强调 | 暂缓或降权 |
|--------|------------|
| 录制质量、等待 URL、工作流组合 | 完整通用 Agent Loop 炫技 |
| 通知与定时 | 云同步 / 多用户 |
| Git → 日报 → 周报闭环 | 可视化万能 Workflow 编辑器（可先做轻量组合） |
